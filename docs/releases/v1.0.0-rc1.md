## PRIMERS OS 1.0 Genesis — release candidate 1

A pre-release for testing, **not** the final 1.0. Ubuntu 22.04 LTS base
(HWE kernel), Openbox desktop, PRIMERS Brain, Primers Lite Bee, Calamares
installer (BIOS and UEFI, Secure Boot capable), Wine and gaming tools, Data
Saver, and the campus modes: Lab Mode, Study Mode and Exam Mode.

> **Exam Mode is not ready for real exams in this RC.** The escape routes
> around the exam kiosk are closed and tested in a virtual machine (see
> below), but a PC that loses power mid-exam, Exam Mode on an installed
> system, and real CBT platforms are not tested yet. Use it for practice
> runs only.

### Tested

All in QEMU virtual machines; nothing in this RC has been run on physical
hardware yet.

| Area | What was checked |
|---|---|
| Boot | Live USB image boots to the desktop on legacy BIOS, UEFI, and UEFI with Secure Boot enforced (Microsoft keys); an unsigned bootloader is refused by the same firmware. |
| Install | Calamares installs to a blank disk on UEFI (GPT, ext4); the installed system boots with its own bootloader to the login screen and desktop. |
| Networking | Wired Ethernet comes up through NetworkManager. Data Saver skips background package downloads on a metered connection. |
| Lite Bee | Real-WebKit tests in CI: home page, Ultra mode loads a page without its images (under 5 KB), Study Mode pauses listed sites, exam kiosk refuses a server not on the exam list. |
| Lab Mode | Live session: passwordless `lab` account; files, downloads, temp files and a process left running are wiped at sign-in, sign-out and by the boot service; `disable` deletes the account; passwordless sign-in is only granted at boot. |
| Study Mode | Live session: Lite Bee pauses youtube.com with no data used, the panel counts down, the end-of-session notice appears. |
| Exam Mode | Live session against a demo exam server: the lab account reaches the exam server and nothing else (other port and internet refused; other accounts unaffected); full-screen kiosk; other servers refused with a notice; Alt+F4, Alt+Tab, Ctrl+Alt+T and right-click do nothing; "Finish exam" signs out; `primers-exam stop` ends a running exam session and removes the firewall; the exam log records sessions, pages, blocked pages and finishes. |
| Exam Mode escape routes | Release workflow, on this exact image booted in a VM (KVM): text consoles (Ctrl+Alt+F1 to F12), Ctrl+Alt+Backspace and Magic SysRq do nothing; no console login prompts; print, clipboard, the clock, DNS (other servers, DNS over HTTPS, tunnelling), a shell, sudo, su and pkexec are refused to the candidate; killing the kiosk ends the session and returns to the login screen, never a desktop; `primers-exam stop` undoes every lock. The release is only published if every check passes. Browser routes (F12, view-source:, file:, data:, javascript:, Ctrl+P/S/O/N/T, downloads, drag and drop, new windows) are tested with real WebKit in CI. Decisions: ADR 0003. |
| Image permissions | Every file in the image belongs to root or a system account and nothing is writable by everyone except /tmp-style sticky directories: checked on the build tree and again on the finished ISO before it is published. |
| Desktop | Console logins and `/etc/os-release` say PRIMERS OS; panel clock; notices open on top. |
| Automated | CI on every push: 265 PRIMERS Brain tests (Python 3.10 and 3.12), 80 Lite Bee tests plus the exam kiosk escape-route test with real WebKit, the image permission gate tests, shellcheck on every shell script, every package name checked against Ubuntu 22.04. |

### Not tested yet, or known gaps

- **Physical hardware** of any kind, including 2G/LTE modem detection.
- **Firmware**: Exam Mode can't stop a candidate who boots something else. Set a firmware password and turn USB and network boot off on exam PCs (pilot guide, "Lock the firmware").
- **Power cuts**: a PC that loses power during an exam is not yet guaranteed to come back in Exam Mode with its exam log intact. The live USB keeps nothing across a reboot; exam machines must be installed.
- **Installed systems**: Lab Mode and Exam Mode have only been tested in the live session. The legacy BIOS install path and the encrypted (LUKS) install are untested.
- **Real CBT platforms** (Moodle, TCExam), exam servers reachable only over IPv6, and exam sites whose CDN addresses change during an exam.
- **Performance targets** (idle RAM under 600 MB, boot under 15 s on SSD or 30 s on HDD) have not been measured on target hardware.
- **Primers ID** is not implemented.
- The ISO is about 2.4 GB.

### Fixed before this RC

Images built by the release workflow on GitHub's runners gave the runner's
user id (1001) ownership of `/`, `/etc`, `/usr`, `/usr/bin` and the files
PRIMERS OS adds. On an installed PC the second account gets that id (often
the Lab Mode account), and owning those folders is the same as being root.
The build now installs every file as root, and two gates refuse an image
with such owners: one on the build tree, one on the finished ISO before
publishing. No image with this fault was published.
